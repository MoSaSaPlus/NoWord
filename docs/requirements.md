## 2. 产品概述

NoWord（无言）是一款个人慈善捐款追踪 Web 应用，用于记录已经完成的捐款，帮助用户查询历史交易、观察捐款趋势，并生成可用于个人财务记录的 PDF 报告。

### 2.1 目标用户

- MVP 仅供系统所有者本人使用。
- 系统只允许存在一个有效用户账户，不开放公众注册。
- 唯一用户账户由部署管理员创建和分配，不提供面向用户的注册功能或管理员后台。
- 虽然是单用户系统，但上线后不得允许匿名访问捐款数据。

### 2.2 产品目标

- 准确记录和维护捐款交易。
- 提供按月、按年统计的捐款趋势。
- 支持生成完整、可阅读的交易 PDF 报告。
- 对删除操作提供 30 天恢复期。
- 达到可部署到线上环境的质量和安全要求。

### 2.3 视觉风格

- 整体风格朴素、克制，以内容可读性和操作清晰度为优先目标。
- 使用中性色作为主要背景和文字颜色，并使用单一低饱和强调色表示主要操作。
- 避免大面积渐变、强烈阴影、复杂装饰和无业务意义的动画。
- 动画仅用于状态变化反馈，并尊重用户减少动态效果的系统设置。

## 3. MVP 范围

### 3.1 包含范围

- 用户登录和退出。
- 全局导航栏、页脚和 About 页面。
- 捐款交易的新增、查询、修改和删除。
- 已删除交易的查看、恢复和到期清理。
- 交易搜索、筛选、排序和分页。
- 月度、年度、同比和平均金额统计。
- 全部有效交易的 PDF 导出。
- 响应式布局、输入校验和统一错误反馈。

### 3.2 暂不包含

- 多用户注册和用户管理。
- 多币种及汇率换算。
- 定期捐款计划。
- 捐款凭证或图片上传。
- 与银行、慈善机构或税务系统集成。
- 原生移动端应用。
- Excel、CSV 等其他格式导出。

## 4. 业务规则

### BR-001 币种

- MVP 仅支持人民币，币种代码为 CNY。
- 所有页面和报告必须明确显示人民币金额。
- 不允许录入或换算其他币种。

### BR-002 金额

- 单笔捐款最小金额为 1.00 元，最大金额为 20,000.00 元，包含边界值。
- 金额最多保留两位小数。
- 金额必须大于零，不接受负数、科学计数法及无法转换为合法金额的内容。
- 金额必须以人民币最小单位“分”的整数形式保存和计算，禁止使用浮点数直接进行业务金额运算。
- 不引入专门的金额计算或金额格式化第三方库，相关逻辑由所选编程语言的基础能力实现。
- 金额展示统一使用千位分隔符和两位小数。

### BR-003 捐款日期

- 捐款日期表示自然日，不包含具体时间和时区。
- 日期必须是真实存在的日历日期。
- 交易代表已经完成的捐款，因此日期不得晚于用户当前日期。

### BR-004 收款方和备注

- 收款方为必填项，去除首尾空白后不得为空。
- 收款方名称长度为 1 至 100 个字符。
- 备注为选填项，长度不得超过 500 个字符。

### BR-005 删除与恢复

- 用户删除交易前必须进行二次确认。
- 删除采用可恢复删除，删除后的交易进入回收站。
- 恢复期限从删除时间开始计算，共 30 天。
- 交易在恢复期内可以恢复，恢复后重新出现在交易列表中。
- 超过恢复期限的交易将被永久清理，之后无法恢复。
- 已删除交易不得计入 Dashboard 统计，也不得出现在普通 PDF 报告中。

### BR-006 年度增减

- 年度增减同时显示金额差和同比百分比。
- 金额差等于本年总额减去上年总额。
- 同比百分比等于金额差除以上年总额。
- 上年总额为零时，不计算同比百分比，界面显示“无法计算”。

### BR-007 平均金额

- 月平均金额等于该月有效捐款总额除以该月有效交易数量。
- 年平均金额等于该年有效捐款总额除以该年有效交易数量。
- 没有交易的月份或年份显示“暂无数据”，不得进行除零运算。

## 5. 功能需求

### 5.1 身份认证

#### FR-AUTH-001 账户创建

- 系统不提供公开注册入口。
- 唯一用户账户由部署管理员通过受控的初始化流程创建。
- MVP 不建设独立的管理员后台或多角色权限系统。

#### FR-AUTH-002 登录保护

- 未登录用户不得访问 Dashboard、交易列表、回收站或 PDF 报告。
- 登录成功后默认进入 Dashboard。
- 登录失败时应显示清晰但不泄露账户信息的错误提示。
- 登录成功后由服务端创建 Session，并通过安全 Cookie 识别后续请求。

#### FR-AUTH-003 退出

- 用户可以主动退出系统。
- 退出后，原会话不得继续访问受保护资源。

### 5.2 全局布局

#### FR-NAV-001 导航栏

- 每个业务页面顶部显示应用名称和汉堡菜单。
- 菜单至少包含 Dashboard、Transactions 和 Recycle Bin。
- 用户可以通过菜单在页面间切换。

#### FR-NAV-002 页脚

- 每个页面底部显示页脚。
- 页脚包含 About 链接。

### 5.3 Dashboard

#### FR-DASH-001 当前年度月度捐款

- 展示当前年度 1 月至 12 月的捐款总额。
- 没有交易的月份按 0 元展示。

#### FR-DASH-002 年度总额

- 展示每个存在有效交易年份的捐款总额。
- 年份按时间顺序清晰排列。

#### FR-DASH-003 年度增减

- 按 BR-006 同时展示年度金额变化和同比百分比。
- 上年数据不存在或为零时，明确显示无法计算百分比。

#### FR-DASH-004 平均金额

- 展示当前年度各月平均捐款金额。
- 展示各年度平均捐款金额。
- 计算规则必须符合 BR-007。

### 5.4 交易管理

#### FR-TXN-001 交易表单

- 表单包含捐款日期、收款方、金额和备注。
- 新增状态下显示“清空”和“新增”操作。
- 修改状态下，提交操作应明确显示为“保存修改”。

#### FR-TXN-002 清空表单

- 用户点击“清空”后，所有输入恢复为空或默认状态。
- 如果表单处于修改状态，清空操作同时退出修改状态并恢复为新增状态。

#### FR-TXN-003 新增交易

- 用户提交表单后，系统必须校验所有字段。
- 校验成功后保存交易，并在列表中显示最新数据。
- 保存成功后清空表单。
- 保存失败时保留用户已经输入的内容，避免重复录入。

#### FR-TXN-004 统一错误反馈

- 一次提交必须展示本次发现的全部字段错误，而不是每次只显示一个错误。
- 错误至少覆盖无效日期、空收款方、非数字金额和超出金额范围。
- 错误信息必须说明问题所在，并可被键盘及辅助技术识别。

#### FR-TXN-005 交易列表

- 列表展示捐款日期、收款方、金额和备注。
- 每条记录提供“修改”和“删除”操作。
- 默认按捐款日期从新到旧排列；日期相同时按创建时间从新到旧排列。
- 列表必须支持分页，避免一次加载全部记录。

#### FR-TXN-006 修改交易

- 用户点击“修改”后，对应交易数据复制到交易表单。
- 用户保存修改前，系统必须重新执行完整校验。
- 修改成功后刷新列表、清空表单并返回新增状态。
- 修改失败时保留用户输入，并显示错误原因。

#### FR-TXN-007 删除交易

- 用户点击“删除”后显示确认对话框。
- 用户取消时，不得改变交易数据。
- 用户确认后，交易进入回收站，并立即从普通列表和统计数据中移除。

#### FR-TXN-008 搜索与筛选

- 支持按捐款日期范围筛选。
- 支持按金额范围筛选，最小金额不得大于最大金额。
- 支持按收款方名称关键字搜索。
- 支持按备注关键字搜索。
- 日期、金额、收款方和备注条件可以组合使用。
- 搜索和筛选条件可以被清除。
- 清除条件后恢复默认列表查询。

#### FR-TXN-009 排序

- 用户可以点击捐款日期、收款方或金额列标题切换升序和降序。
- 当前排序字段和排序方向必须在界面中清晰可见。
- 排序必须作用于完整查询结果，而不仅是当前页数据。

### 5.5 回收站

#### FR-REC-001 查看已删除交易

- 回收站展示仍处于 30 天恢复期内的交易。
- 每条记录显示原交易信息、删除时间和剩余可恢复时间。

#### FR-REC-002 恢复交易

- 用户可以恢复仍在有效期内的交易。
- 恢复成功后，交易重新进入普通列表并重新计入统计。

#### FR-REC-003 到期处理

- 超过 30 天的交易不得继续显示为可恢复。
- 系统必须确保过期交易最终被永久清理。

### 5.6 PDF 报告

#### FR-PDF-001 导出报告

- 用户可以在交易列表附近发起 PDF 导出。
- 用户可以指定 PDF 报告的开始日期和结束日期。
- 未指定日期范围时，PDF 默认包含全部有效交易。
- PDF 中的交易按捐款日期从新到旧排列。
- PDF 至少包含 NoWord 名称、开发者信息、报告标题、生成时间、报告日期范围、交易字段、交易总笔数和捐款总额。
- 多页 PDF 必须显示页码。
- 报告中的金额必须符合 BR-001 和 BR-002。
- 已删除且尚未恢复的交易不得出现在报告中。
- 报告生成失败时必须向用户提供明确反馈。

### 5.7 About 页面

#### FR-ABOUT-001 开发者信息

- About 页面展示开发者简介。
- 页面提供 GitHub 和至少一个社交平台链接。
- 外部链接应明确标识并采用安全的打开方式。

## 6. 非功能需求

### NFR-001 安全

- 生产环境必须使用 HTTPS。
- 交易、身份凭据和会话信息不得存储在浏览器 `localStorage` 中。
- 身份会话应使用具备 `HttpOnly`、`Secure` 和适当 `SameSite` 策略的 Cookie。
- Session 状态由服务端管理，MVP 不使用浏览器持久化 JWT 作为登录方案。
- 用户密码必须使用成熟安全库提供的 Argon2id 等适合密码存储的算法进行哈希，禁止保存明文密码或自行设计加密算法。
- 所有输入必须在服务端重新校验，不能信任前端校验结果。
- 数据库凭据、会话密钥等敏感配置不得提交到版本库。
- 错误响应和日志不得暴露密码、密钥或完整的敏感交易数据。

### NFR-002 数据正确性

- 金额的保存、统计和导出必须遵守整数金额规则。
- 新增、修改、删除和恢复操作必须保证数据状态一致。
- Dashboard 与 PDF 使用的统计口径必须与交易列表一致。

### NFR-003 可用性与无障碍

- 页面应适配桌面和移动端常见宽度。
- 所有主要功能必须能够通过键盘完成。
- 表单字段、按钮、对话框和图表应提供清晰标签或等价文本说明。
- 不得只依赖颜色表达错误、状态或图表含义。

### NFR-004 性能

- 在单用户累计 10,000 条交易的情况下，常用列表查询和 Dashboard 加载目标为 2 秒内完成。
- 列表采用服务端分页、筛选和排序。
- Dashboard 统计由服务端或数据库聚合，不得将全部交易下载到浏览器后计算。

### NFR-005 可靠性

- 生产数据库每天自动备份一次，自动备份至少保留 14 天。
- 每周生成一次加密的逻辑备份，并在独立于生产数据库的存储位置保留至少 8 周。
- 至少每季度执行一次数据库恢复演练，确认备份真实可用。
- MVP 的恢复点目标为 24 小时，恢复时间目标为 4 小时。
- 关键操作失败时不得产生部分保存或不一致状态。
- 系统应记录服务端错误，以便定位线上问题。

### NFR-006 浏览器支持

- 支持当前主流桌面及移动浏览器的最新两个稳定版本。

### NFR-007 审计

- 系统应记录登录、新增、修改、删除、恢复和 PDF 导出等关键操作的时间、结果及目标记录标识。
- 审计记录不得保存密码、会话密钥或完整备注等非必要敏感内容。
- 普通业务操作不得修改或删除审计记录。

### NFR-008 部署

- NoWord 以 Web 应用形式部署，不提供原生桌面端或移动端客户端。
- 生产环境使用 `mosasanb.com` 域名并启用 HTTPS。
- 前端页面和业务 API 应优先采用同源部署，减少跨域配置和会话安全风险。
- 具体云服务商、服务器地域和托管数据库供应商在部署设计阶段确定。

## 7. 验收与完成标准

一个功能只有同时满足以下条件才视为完成：

- 对应需求和验收条件已经明确。
- 正常流程、错误流程和边界值均经过测试。
- 金额、日期和删除恢复规则符合业务规则。
- 未引入未授权访问或敏感数据泄露风险。
- 代码通过格式检查、静态检查、自动化测试和构建。
- 相关文档已经同步更新。
- 经过自我代码审查，并在合并前通过 CI。

## 8. 待技术设计事项

以下事项不再属于产品需求问题，将在对应技术设计任务中确定：

1. 账户初始化采用命令行工具、部署脚本还是受保护的内部接口。
2. Session 的存储结构、有效期限和主动失效机制。
3. 具体云服务商、服务器地域和托管 PostgreSQL 供应商。
4. 自动备份与异地逻辑备份所使用的具体存储服务。
5. PDF 的具体版式、字体和开发者信息内容。

## 9. 已确认的产品决策

- 产品正式名称为 NoWord（无言），视觉风格朴素、克制。
- 系统仅供本人使用。
- 唯一账户由部署管理员分配，不开放注册，也不建设管理员后台。
- 身份认证采用服务端 Session 和安全 Cookie。
- MVP 只支持人民币。
- 单笔金额范围为 1.00 元至 20,000.00 元，最多两位小数。
- 收款方最多 100 个字符，备注最多 500 个字符。
- 删除后的交易可在 30 天内恢复。
- 年度变化同时展示金额和百分比。
- 搜索与筛选包含日期范围、金额范围、收款方和备注关键字。
- PDF 导出属于 MVP，并包含开发者信息、页码和自定义日期范围。
- 产品以 Web 应用形式部署，生产域名为 `mosasanb.com`。
- 数据库采用每日自动备份、每周异地加密备份和定期恢复演练。
- 产品目标是达到可上线版本，而不是只在本地运行。
